## 收藏夹工作区管理系统 -- 产品详细设计文档 v2.1.0

### 1. 项目概述

**项目背景**：作为一个兴趣广泛的探索者，我的浏览器收藏夹在过去十多年里不断膨胀，累积了数千个链接。为了理清这些知识资产，我将其进行了逐层分类，却意外陷入了"分类陷阱"：为了找到某个特定URL，往往需要像剥洋葱一样逐层展开3到4级目录，体验十分割裂。由于始终找不到一款能兼顾深度分类与便捷调用的现成工具，我决定亲手打造一款符合自己直觉的解决方案，这便是本项目的诞生初衷。

**Bookmark Workspace Manager（收藏夹工作区管理系统）** 是一款跨浏览器扩展（Chrome / Edge / Firefox / QQ Browser），将传统书签栏中的顶层文件夹抽象为"工作区（workspace）"，并提供多列树状视图、全局搜索、多主题切换、面板缩放、双面板对比视图、拖放交互，以及基于 GitHub Gist 的书签同步（上传/下载/清空）能力。

**版本**：v2.1.0，版本号统一由根目录 `VERSION` 文件管理，格式为 `x.x.x`（3 段整数），打包时自动递增第 3 位。

### 2. 目标用户

- 拥有大量书签并希望按项目/类别快速切换的从业者
- 需要同时查看多级目录结构的技术人员
- 偏好现代化、可自定义界面的效率工具用户
- 需要在多设备间同步书签的跨浏览器用户

### 3. 核心价值

- 屏蔽"书签栏/其他书签"等无关层级，直接聚焦用户自定义的顶层分类
- 横向多列展开，直观体现文件夹层级关系
- 搜索、缩放、主题切换、双面板对比、拖放加载等提升可访问性与工作效率
- 界面状态自动保存，重启即恢复
- 基于 GitHub Gist 的书签同步：上传、下载、清空本地书签
- 跨浏览器兼容：Chrome / Edge / Firefox / QQ Browser，自动适配各浏览器书签结构
- 用户可手动配置书签根目录识别策略，解决 QQ 同步数据在 Chrome/Firefox 中位置异常的问题

```
bookmark-workspace/

│   ├── utils.js            # 工具函数（HTML转义、书签计数、Toast、层级边框）
```

### 5. 脚本加载与依赖关系

**popup.html 加载顺序（不可变更）**：
```
utils.js → bookmarks.js → state.js → ui.js → controller.js
```
所有文件使用 `var` 声明（无 ES 模块）。`state.js` 声明全局变量，`controller.js` 消费它们。

**background.js（Service Worker / Background Page）**：
- Chrome：使用 `importScripts('js/sync-settings.js', 'js/sync-gist.js')`（Service Worker 上下文）
- Firefox：构建时自动合并 sync-settings.js + sync-gist.js 内容到 background.js 中（Firefox background.scripts 不支 `importScripts`）

**settings.html**：
```
<script src="js/sync-settings.js"></script>
<script src="js/settings.js"></script>
```

### 6. 功能需求详述

#### 6.1 核心概念：工作区（Workspace）

- **定义**：浏览器"书签栏"节点下的直接子文件夹
- **书签栏识别策略**（8 级兜底，支持 `preferredRoot` 参数）：

| 优先级 | 匹配方式 | 目标 |
|--------|----------|------|
| 1 | id === '1' | Chrome 书签栏 |
| 2 | id === 'unfiled_____' | Firefox 其他书签（QQ同步数据常见位置） |
| 3 | id === '2' | Chrome 其他书签（QQ同步数据常见位置） |
| 4 | id === 'toolbar_____' | Firefox 书签工具栏 |
| 5 | 标题匹配 | 书签栏 / bookmarks bar / toolbar |
| 6 | 标题匹配 | 其他书签 / other bookmarks |
| 7 | 兜底 | 首个有文件夹子项的节点（排除 mobile） |
| 8 | 最后手段 | 任意有子项的节点 |

- 用户可通过设置页面「书签路径」Tab 手动选择识别策略（auto / bookmarks_bar / other_bookmarks / menu_folder）
- 该策略存储在 `chrome.storage.sync`，键名 `bookmarkRootPath`

#### 6.2 页面布局

```
┌─────────────────────────────────────────────────────────┐
│ 标题栏  [名称 v2.1.0] [搜索] [主题色点] [⬆⬇🗑⚙ℹ️🗑⿰]  │
├─────────────────────────────────────────────────────────┤
│ 工具栏 (半透明)                                          │
│  [拖拽提示] [🌐全部] [01办公] [02硬件] ...               │
├─────────────────────────────────────────────────────────┤
│ 展示区 (默认单面板，可切换双面板)                         │
│ ┌─────────────┬────┬──────────────┐                     │
│ │ 面板1 (激活) │ 分隔│ 面板2      │                     │
│ └─────────────┴────┴──────────────┘                     │
└─────────────────────────────────────────────────────────┘
```

#### 6.3 标题栏

- 高度 52px，透明背景，与页面融合
- 左侧显示工具名称 + 英文副标题 + 动态版本号（通过 `chrome.runtime.getManifest().version` 读取）
- 右侧依次排列：
  - 搜索框（200px，圆角，搜索图标 + 清除按钮）
  - 主题切换（四个圆形按钮，四套主题）
  - 同步按钮组：上传（⬆）、下载（⬇）、清空书签（🗑，红色警示）、设置（⚙）
  - 功能按钮组：关于（ℹ️）、清理缓存（🗑️）、双面板（⿰）

#### 6.4 搜索栏

- 整合在标题栏右侧
- 输入实时过滤所有书签（标题、URL、路径），200ms 防抖
- 搜索结果列表替换面板1，显示标题、面包屑路径、URL
- `Escape` 或清除按钮退出搜索，恢复列视图

#### 6.5 工具栏（筛选区）

- 半透明背景 + 模糊滤镜，圆角 10px
- 拖拽提示：鼠标悬浮工具栏时显示
- 筛选按钮：选中态有主题色背景 + 边框 + 文字加粗；可拖拽至面板加载

#### 6.6 展示区

- **默认单面板**，面板2隐藏；可通过 ⿰ 按钮切换双面板
- **面板激活**：鼠标移入或点击切换激活态（标题栏高亮）
- **面板控制**：清空按钮 + 缩放控件（A-/A+，范围 0.6x~1.8x）
- **列布局**：flex-wrap，列宽 220px × 缩放系数，层级左侧有色线条
- **交互**：点击文件夹展开/折叠，点击书签新标签页打开，支持拖入筛选按钮加载

#### 6.7 四套主题

| 主题 | CSS 类 | 背景色 | 强调色 | 层级 RGB |
|------|--------|--------|--------|----------|
| 暗夜黑金（默认） | dark-gold | #0A0A0A | #D4AF37 | 212,175,55 |
| 烈焰暗红 | dark-crimson | #141414 | #DC2626 | 220,38,38 |

主题状态持久化在 `localStorage`（键名 `workspace_theme`）和 `chrome.storage.sync`（键名 `theme`）双写，确保弹窗和设置页主题一致。

#### 6.8 状态持久化

**localStorage（弹窗面板状态）**，键名前缀 `workspace_`：

| 键名 | 类型 | 说明 |
|------|------|------|
| `workspace_theme` | string | 主题名称 |
| `workspace_panel1Path` | JSON | 面板1书签路径 |
| `workspace_panel2Path` | JSON | 面板2书签路径 |
| `workspace_panel1Scale` | float | 面板1缩放（0.6~1.8） |
| `workspace_panel2Scale` | float | 面板2缩放（0.6~1.8） |
| `workspace_activePanel` | string | 当前激活面板 |

**chrome.storage.sync（统一设置）**：

| 键名 | 类型 | 说明 |
|------|------|------|
| `githubToken` | string | GitHub Personal Access Token |
| `gistID` | string | Gist ID |
| `gistFileName` | string | Gist 文件名（默认 BookmarkHub） |
| `enableNotify` | boolean | 是否启用浏览器通知 |
| `theme` | string | 主题名称 |
| `bookmarkRootPath` | string | 书签根目录识别策略（auto / bookmarks_bar / other_bookmarks / menu_folder） |

#### 6.9 书签同步（基于 GitHub Gist）

**前置条件**：用户需在设置页面（⚙ 按钮）配置 GitHub Personal Access Token（需 `gist` 权限）和 Gist ID。

**上传**：点击 ⬆ 按钮
1. `chrome.bookmarks.getTree()` 获取书签树
2. 格式化去除浏览器特有字段（id, index, parentId 等），统一根文件夹名称（跨浏览器 ID 映射）
3. 构建 SyncDataInfo JSON → `PATCH /gists/:gistID` 上传
4. Toast 反馈结果

**下载**：点击 ⬇ 按钮（含确认对话框）
1. `GET /gists/:gistID` 获取 Gist 数据
2. 若文件被截断，通过 `raw_url` 拉取完整内容
3. `chrome.bookmarks.removeTree()` 清空本地书签
4. `chrome.bookmarks.create()` 逐节点重建书签树（使用 `ensureFolderIds` 动态检测浏览器根文件夹 ID）
5. 刷新弹窗视图（清除旧路径，重新加载书签树）
6. Toast 反馈结果

**清空**：点击红色 🗑 按钮（含二次确认）
1. 遍历根文件夹下所有一级子节点
2. `chrome.bookmarks.removeTree()` 逐个删除

**跨浏览器 ID 映射**（`sync-gist.js`）：

| 文件夹含义 | Chrome ID | Firefox ID | 统一名称（存储用） |
|-----------|-----------|------------|-------------------|
| 书签栏/工具栏 | `"1"` | `"toolbar_____"` | `ToolbarFolder` |
| 其他书签 | `"2"` | `"unfiled_____"` | `UnfiledFolder` |
| 移动设备 | `"3"` | `"mobile______"` | `MobileFolder` |
| 书签菜单 | - | `"menu________"` | `MenuFolder` |

- 上传时：`formatBookmarks()` 通过 `classifyRootFolderTitle()` 将各浏览器特有 ID 映射为统一名称
- 下载时：`ensureFolderIds()` 动态检测当前浏览器根文件夹 ID，`_createBookmarkTree()` 使用检测结果创建书签

**消息通信**：popup 通过 `chrome.runtime.sendMessage()` 向 background service worker 发送 `upload` / `download` / `clearAll` / `openSettings` 消息，SW 处理完成后回调响应。

#### 6.10 统一设置页面

设置页面位于 `settings.html`，采用三标签页布局：

**Tab 1：同步设置**
- GitHub Token（密码输入框，可切换显示/隐藏）
- Gist ID
- Gist 文件名
- 通知开关

**Tab 2：主题设置**
- 四套主题卡片展示（色块 + 名称 + 描述）
- 点击选中，保存后同步到 `chrome.storage.sync` 和 `localStorage`

**Tab 3：书签路径**
- 下拉选择书签根目录识别策略
- 选项：自动检测 / 书签栏 / 其他书签 / 书签菜单（Firefox）
- 选择后显示策略说明预览
- 解决 QQ 浏览器书签同步到 Chrome/Firefox 后被放入「其他书签」导致插件不识别的问题

### 7. 版本管理

- 版本号唯一来源：根目录 `VERSION` 文件（纯文本，格式 `x.x.x`，如 `2.1.0`）
- 第 3 位（Patch）为构建号，范围 0-999
- 打包时：`deployment/build.sh` 读取 VERSION → 自动递增第 3 位 → 写回 VERSION → 注入 manifest.json → 打包 → 恢复
- 开发时：`manifest.json` 保持与 `VERSION` 同步

### 8. 构建与交付

**本地打包**：
```bash
bash deployment/build.sh
```

输出：
- `dist/bookmark-workspace-manager-chrome-v{VERSION}.zip` — Chrome/Edge 版
- `dist/bookmark-workspace-manager-chrome-v{VERSION}.crx` — Chrome 侧载签名版
- `dist/bookmark-workspace-manager-firefox-v{VERSION}.zip` — Firefox 版

**打包流程**：
1. 从 `VERSION` 文件读取版本号，自动递增第 3 位
2. 备份原始 manifest.json 和 background.js
3. **Firefox 构建**：
   - 合并 sync-settings.js + sync-gist.js 到 background.js（Firefox 不支持 `importScripts`）
   - manifest 使用 `background.scripts` + `browser_specific_settings.gecko`
   - 打包 Firefox ZIP
4. **Chrome 构建**：
   - 恢复原始 background.js
   - manifest 使用 `background.service_worker`，移除 `browser_specific_settings`
   - 打包 Chrome ZIP + CRX
5. 恢复原始文件

**Firefox 安装方式**：
1. 解压 Firefox ZIP 到文件夹
2. 地址栏打开 `about:debugging#/runtime/this-firefox`
3. 点击「加载临时附加组件」
4. 选择解压目录中的 `manifest.json` 文件

**Chrome 安装方式**：
1. 解压 Chrome ZIP 到文件夹
2. `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序

**签名密钥管理**：
- 私钥存储在 `deployment/key.pem`（已由 `.gitignore` 排除 `*.pem`）
- 首次运行自动生成，后续构建复用同一密钥以确保扩展 ID 不变
- CI 环境中通过 GitHub Secret `CRX_SIGNING_KEY` 注入密钥内容

**排除内容**：`.git/`, `.github/`, `docs/`, `deployment/`, `dist/`, `reference/`, `temp/`, `README.md`, `AGENTS.md`, `LICENSE`, 临时文件等。

### 9. 设计决策与注意事项

- **书签栏识别兼容性**：8 级兜底 + 用户可配置策略，覆盖 Chrome / Edge / Firefox / QQ Browser 各书签结构
- **QQ 同步数据兼容**：QQ 浏览器将「普通书签」作为书签栏，同步到 Chrome/Firefox 后数据被放入「其他书签」。插件通过第 2/3 优先级（id: unfiled_____ / '2'）和用户手动配置策略解决
- **Firefox background 兼容**：Firefox 使用 `background.scripts`（页面上下文）而非 `background.service_worker`，构建时自动合并依赖文件到 background.js，避免 `importScripts` 不可用问题
- **数据实时性**：每次打开新标签页重新调用 `chrome.bookmarks.getTree()`
- **搜索性能**：初始化时构建一次扁平化数组，后续搜索仅为内存匹配
- **无外部依赖**：纯原生 JS/CSS，无 npm / React / 构建工具
- **版本统一管理**：`VERSION` 文件为唯一版本来源，构建脚本自动递增
- **安全性**：GitHub Token 存储在 `chrome.storage.sync`，输入框使用 `type="password"`；清空/下载操作有 `confirm()` 二次确认
- **跨域权限**：manifest 声明 `host_permissions` 允许访问 `api.github.com` 和 `gist.githubusercontent.com`
