## 收藏夹工作区管理系统 -- 产品详细设计文档 v2.2.30

### 1. 项目概述

**项目背景**：作为一个兴趣广泛的探索者，我的浏览器收藏夹在过去十多年里不断膨胀，累积了数千个链接。为了理清这些知识资产，我将其进行了逐层分类，却意外陷入了"分类陷阱"：为了找到某个特定URL，往往需要像剥洋葱一样逐层展开3到4级目录，体验十分割裂。由于始终找不到一款能兼顾深度分类与便捷调用的现成工具，我决定亲手打造一款符合自己直觉的解决方案，这便是本项目的诞生初衷。

**Bookmark Workspace Manager（收藏夹工作区管理系统）** 是一款跨浏览器扩展（Chrome / Edge / Firefox / QQ Browser），将传统书签栏中的顶层文件夹抽象为"工作区（workspace）"，并提供多列树状视图、全局搜索、多主题切换、面板缩放、双面板对比视图、拖放交互、列宽/高拖拽调整，以及基于 GitHub Gist 的书签同步（上传/下载/清空/覆盖追加）能力。

**版本**：v2.2.30，版本号统一由根目录 `VERSION` 文件管理，格式为 `x.x.x`（3 段整数），打包时自动递增第 3 位。

### 2. 目标用户

- 拥有大量书签并希望按项目/类别快速切换的从业者
- 需要同时查看多级目录结构的技术人员
- 偏好现代化、可自定义界面的效率工具用户
- 需要在多设备间同步书签的跨浏览器用户
- 使用 QQ 浏览器（未登录账户）的同步需求用户

### 3. 核心价值

- 屏蔽"书签栏/其他书签"等无关层级，直接聚焦用户自定义的顶层分类
- 横向多列展开，直观体现文件夹层级关系
- 搜索（favicon + 域名提取 + 高亮）、缩放、主题切换、双面板对比、拖放加载、列拖拽调整
- 界面状态自动保存，重启即恢复
- 基于 GitHub Gist 的书签同步：上传、下载（覆盖/追加模式）、清空本地书签
- 下载存储文件夹机制，统一管理同步数据
- 跨浏览器兼容：Chrome / Edge / Firefox / QQ Browser，自动适配各浏览器书签结构
- 书签根目录识别策略按浏览器分类（Chrome/Edge / Firefox / QQ浏览器 / 自定义）
- QQ 浏览器未登录模式适配：`ensureFolderIds` 重定向 + 快照虚拟树 + 创建 ID 追踪清空

### 5. 脚本加载与依赖关系

**popup.html 加载顺序（不可变更）**：
```
utils.js → sync-settings.js → bookmarks.js → state.js → ui.js → controller.js
```
所有文件使用 `var` 声明（无 ES 模块）。`state.js` 声明全局变量，`controller.js` 消费它们。

**background.js（Service Worker / Background Page）**：
- Chrome：使用 `importScripts('js/sync-settings.js', 'js/sync-gist.js')`（Service Worker 上下文）
- Firefox：构建时自动合并 sync-settings.js + sync-gist.js 内容到 background.js 中（Firefox background.scripts 不支 `importScripts`）

**settings.html**：
```
<script src="js/sync-settings.js"></script>
<script src="js/settings.js"></script>
```

### 6. 功能需求详述

#### 6.1 核心概念：工作区（Workspace）

- **定义**：浏览器"书签栏"节点下的直接子文件夹
- **书签栏识别策略**（按浏览器分类 + 全量兜底）：
  - 各浏览器独立的 `detectXxx` 函数：`detectChromeBar`、`detectChromeOther`、`detectFirefoxToolbar`、`detectFirefoxOther`、`detectFirefoxMenu`、`detectQQBar`、`detectQQOther`
  - `detectAuto` 自动检测：标准 ID → 标题匹配 → 全量遍历所有 root children
  - 全量兜底：遍历所有 `root.children`，优先返回有文件夹子项的，其次返回有任意子项的
  - `detectByTitle` 标题匹配：支持 "书签栏"、"所有书签"、"收藏栏"、"other bookmarks" 等
  - 空子节点保护：`children.length > 0` 判断，杜绝空数组真值误判

- 用户可通过设置页面「书签路径」Tab 手动选择识别策略：
  - Chrome/Edge：书签栏 / 其他书签
  - Firefox：书签工具栏 / 其他书签 / 书签菜单
  - QQ浏览器：书签栏（含登录/未登录适配）/ 其他书签（QQ同步默认位置）
  - 用户指定文件夹名称 / 自动检测（推荐）
- 该策略存储在 `chrome.storage.sync`，键名 `bookmarkRootPath`

#### 6.3 标题栏

- 高度 52px，透明背景，与页面融合
- 左侧显示工具名称 + 英文副标题 + 动态版本号（通过 `chrome.runtime.getManifest().version` 读取）

  - 功能按钮组：关于（ℹ️）、清理缓存（🗑️）、双面板（⿰）

#### 6.9 书签同步（基于 GitHub Gist）

**前置条件**：用户需在设置页面配置 GitHub Personal Access Token（需 `gist` 权限）和 Gist ID。设置页提供一键填充功能，粘贴认证信息文本自动识别并填入 Token / Gist ID / 文件名。

**下载模式**（radio 卡片选择）：
- **覆盖**：先清空本地书签，再从 Gist 完整写入（默认）
- **追加**：保留本地书签，仅新增 Gist 中不存在的条目

**下载存储文件夹**（可选）：设置后，下载的书签统一存入书签栏下指定名称的文件夹中，工作区仅从此文件夹读取，确保下载和读取路径一致。

**上传**：点击上传按钮
1. 前置检查：无 GitHub 认证信息时直接 toast 提示，不发送消息
2. `chrome.bookmarks.getTree()` 获取书签树
3. 格式化去除浏览器特有字段，统一根文件夹名称
4. 构建 JSON → `PATCH /gists/:gistID` 上传
5. Toast 反馈结果

**下载**：点击下载按钮（含确认对话框）
1. 前置检查：无 GitHub 认证信息时直接 toast 提示
2. `GET /gists/:gistID` 获取 Gist 数据
3. 覆盖模式：清空本地书签后重建；追加模式：直接合并
4. `chrome.bookmarks.create()` 逐节点重建书签树
5. 追踪创建的书签 ID 存入 `chrome.storage.local`（`gistBookmarkIds`）
6. 存储 Gist 快照数据（`gistBookmarkSnapshot`），用于 QQ 浏览器虚拟树展示
7. 刷新弹窗视图，Toast 反馈结果

**清空**：点击清空按钮（含二次确认）
1. 标准清空：遍历根文件夹下所有一级子节点，`removeTree()` 逐个删除
2. 存储 ID 清空：`tryClearViaStoredIds` 读取 `gistBookmarkIds`，反向 `remove()` 逐个删除
3. 无 GitHub 认证也可执行（本地操作）

**QQ 浏览器适配**（`sync-gist.js`）：
- `ensureFolderIds` 检测标准 id='2'（其他书签）为空时，将 `ids.other` 重定向到 `ids.toolbar`（书签栏），绕开 QQ 独立存储层
- 下载时追踪 `_createdBookmarkIds`，清空时按 ID 调用 `remove()` 删除
- 下载时存储 `gistBookmarkSnapshot`，弹出窗口 `getTree()` 返回空时从快照构建虚拟树展示
- `getBookmarks()` 三层兜底：`getTree()` → `search({})` → `getChildren("0")`

**跨浏览器 ID 映射**（`sync-gist.js`）：

| 文件夹含义 | Chrome ID | Firefox ID | 统一名称（存储用） |
|-----------|-----------|------------|-------------------|
| 书签栏/工具栏 | `"1"` | `"toolbar_____"` | `ToolbarFolder` |
| 其他书签 | `"2"` | `"unfiled_____"` | `UnfiledFolder` |
| 移动设备 | `"3"` | `"mobile______"` | `MobileFolder` |
| 书签菜单 | - | `"menu________"` | `MenuFolder` |

- 上传时：`formatBookmarks()` 通过 `classifyRootFolderTitle()` 将各浏览器特有 ID 映射为统一名称
- 下载时：`ensureFolderIds()` 动态检测当前浏览器根文件夹 ID，`_createBookmarkTree()` 使用检测结果创建书签

**消息通信**：popup 通过 `chrome.runtime.sendMessage()` 向 background service worker 发送 `upload` / `download` / `clearAll` / `openSettings` 消息，SW 处理完成后回调响应。

### 7. 版本管理

- 版本号唯一来源：根目录 `VERSION` 文件（纯文本，格式 `x.x.x`，如 `2.1.0`）
- 第 3 位（Patch）为构建号，范围 0-999
- 打包时：`deployment/build.sh` 读取 VERSION → 自动递增第 3 位 → 写回 VERSION → 注入 manifest.json → 打包 → 恢复
- 开发时：`manifest.json` 保持与 `VERSION` 同步

### 8. 构建与交付

**本地打包**：
```bash
bash deployment/build.sh
```

输出：
- `dist/bookmark-workspace-manager-chrome-v{VERSION}.zip` — Chrome/Edge 版
- `dist/bookmark-workspace-manager-chrome-v{VERSION}.crx` — Chrome 侧载签名版
- `dist/bookmark-workspace-manager-firefox-v{VERSION}.zip` — Firefox 版

**打包流程**：
1. 清空 `dist/` 目录旧构建产物
2. 从 `VERSION` 文件读取版本号，自动递增第 3 位
3. 备份原始 manifest.json 和 background.js
3. **Firefox 构建**：
   - 合并 sync-settings.js + sync-gist.js 到 background.js（Firefox 不支持 `importScripts`）
   - manifest 使用 `background.scripts` + `browser_specific_settings.gecko`
   - 打包 Firefox ZIP
4. **Chrome 构建**：
   - 恢复原始 background.js
   - manifest 使用 `background.service_worker`，移除 `browser_specific_settings`
   - 打包 Chrome ZIP + CRX
5. 恢复原始文件

**Firefox 安装方式**：
1. 解压 Firefox ZIP 到文件夹
2. 地址栏打开 `about:debugging#/runtime/this-firefox`
3. 点击「加载临时附加组件」
4. 选择解压目录中的 `manifest.json` 文件

**Chrome 安装方式**：
1. 解压 Chrome ZIP 到文件夹
2. `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序

**签名密钥管理**：
- 私钥存储在 `deployment/key.pem`（已由 `.gitignore` 排除 `*.pem`）
- 首次运行自动生成，后续构建复用同一密钥以确保扩展 ID 不变
- CI 环境中通过 GitHub Secret `CRX_SIGNING_KEY` 注入密钥内容

**排除内容**：`.git/`, `.github/`, `docs/`, `deployment/`, `dist/`, `reference/`, `temp/`, `README.md`, `AGENTS.md`, `LICENSE`, 临时文件等。

### 9. 设计决策与注意事项

- **书签栏识别兼容性**：按浏览器分类策略 + 全量兜底，覆盖 Chrome / Edge / Firefox / QQ Browser 各书签结构
- **QQ 浏览器适配**：QQ 浏览器"其他书签"是独立存储层，`chrome.bookmarks` API 无法读写。通过 `ensureFolderIds` 重定向到书签栏 + 快照虚拟树 + 创建 ID 追踪清空三重机制绕开限制
- **Firefox background 兼容**：Firefox 使用 `background.scripts`（页面上下文）而非 `background.service_worker`，构建时自动合并依赖文件到 background.js
- **数据实时性**：每次打开新标签页重新调用 `chrome.bookmarks.getTree()`，QQ 浏览器模式下优先使用 Gist 快照
- **搜索性能**：初始化时构建一次扁平化数组，后续搜索仅为内存匹配
- **无外部依赖**：纯原生 JS/CSS，无 npm / React / 构建工具
- **版本统一管理**：`VERSION` 文件为唯一版本来源，构建脚本自动递增
- **安全性**：GitHub Token 存储在 `chrome.storage.sync`，输入框使用 `type="password"`；清空/下载操作有 `confirm()` 二次确认；上传/下载按钮无认证时直接提示不发送消息
- **跨域权限**：manifest 声明 `host_permissions` 允许访问 `api.github.com` 和 `gist.githubusercontent.com`
- **变更日志**：`CHANGELOG.md` 记录每次版本的功能变更和缺陷修复
